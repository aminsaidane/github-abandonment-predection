# Predicting GitHub Repository Abandonment

Can we tell, early in a repository's life, whether it will be abandoned? This project labels a repository **abandoned** when it received no push in the 365 days before the dataset snapshot (13 September 2025). It then studies which signals separate abandoned repositories from active ones, using:

- a stratified sample of 5,000 public repositories with 5+ stars that were at least 2 years old at the snapshot;
- each repository's activity in its **first 6 months**, collected from the GitHub API.

The ETL runs in **Apache Hop**; the analysis and modeling run in **Python**.

## Setup

Requires **Python 3.10+** and **Apache Hop**.

```bash
python -m venv venv
venv\Scripts\activate              # Windows  (Mac/Linux: source venv/bin/activate)
pip install -r requirements.txt
```

Two credentials are needed. Neither is ever committed, since both are listed in `.gitignore`:

- **Kaggle API token** (`kaggle.json`), to download the dataset. See `sample_dataset.MD`, step 1.
- **GitHub personal access token**, read-only access to public repositories, for the early-activity collection. Put it in a `.env` file at the repo root:

  ```
  GITHUB_TOKEN=github_pat_...
  ```

In Hop, create a project whose home folder (`${PROJECT_HOME}`) is the repository root.

## How to run

Run everything from the repository root.

| # | Step | Command | Reads → writes |
|---|---|---|---|
| 1 | Download the dataset | `kaggle datasets download -d pelmers/github-repository-metadata-with-5-stars -p ./data --unzip` | → `data/*.json` |
| 2 | Label and sample | `python scritpts/sampleDataset.py --input data/<file>.json --output data/repos_sample_5000.json` | → `data/repos_sample_5000.json` |
| 3 | Hop pipelines 1–2 | run `hop/ingest_and_label.hpl`, then `hop/feature_engeneering.hpl` | → `data/pipeline2_output.csv`, `data/rejected_rows.csv` |
| 4 | Collect early activity (one-off, about 4 h, resumable) | `python scritpts/collect_early_activity.py` (try `--limit 20` first) | `pipeline2_output.csv` → `data/early_activity.csv` |
| 5 | Hop pipeline 3 | run `hop/merge_early_activity.hpl` | → `data/pipeline3_output.csv`, `data/rejected_early.csv` |
| 6 | EDA | open `notebooks/eda.ipynb`, select the `venv` kernel, Run All | → `reports/figures/eda/`, `reports/tables/` |
| 7 | Model (beyond the midterm scope) | `python -m src.train`, then `python -m src.evaluate` | → `models/best_model.pkl`, `reports/` |

Once `data/early_activity.csv` exists, `hop/workflow.hwf` runs steps 3 and 5 in a single click.

## Key methodological decisions

- **Leakage exclusions:** `days_since_last_push` and `pushedAt` define the label, and 94% of archived repos are abandoned (`isArchived`). They're kept in the data but never used as features (`src/config.py`). See notebook §5.2.
- **No information from the test set:** imputation, outlier caps, log transforms, scaling and encoding are all learned on the training split only (`src/preprocess.py`). See notebook §5.3.
- **Outliers are kept:** extreme values belong to real repositories. Three variables whose extremes are real but misleading (inherited kernel history, organisation-wide collaborator counts) are capped at the training 99th percentile. See notebook §2.4–2.5.
- **Missing values carry information:** a missing license or description becomes a 0/1 feature instead of a dropped row. See notebook §2.2.
- **Non-parametric tests:** the counts are heavily skewed, so groups are compared with Mann–Whitney U and χ² tests, reported with effect sizes and a Holm correction. See notebook §4.

## Data source

*GitHub Public Repository Metadata* (all public repositories with 5+ stars), published on Kaggle by user `pelmers`: <https://www.kaggle.com/datasets/pelmers/github-repository-metadata-with-5-stars>. See the dataset page for its license and terms of use. Early-life activity is collected from the [GitHub REST API](https://docs.github.com/en/rest). Since July 2026, stargazer timestamps are only available to a repository's own collaborators, so early stars are not collected.
